# E 项目说明文档

本项目是一个面向电赛/嵌入式视觉控制场景的综合工程，由 K230 视觉识别端和 MSPM0G3507 控制端组成。K230 负责摄像头图像采集、黑色矩形框识别、中心坐标计算和串口发送；MSPM0G3507 控制端包含小车底盘循迹工程和云台步进电机工程，分别完成小车运动控制、灰度循迹、编码器测速、PID 调节以及云台目标对准。

## 二、系统功能概述

### 1. K230 视觉识别

K230 运行 CanMV Python 程序，通过摄像头实时采集画面，使用 `cv_lite` 识别黑色矩形框，并计算目标矩形中心坐标。程序会在屏幕上绘制识别结果，同时通过 UART2 将目标坐标和矩形面积发送给 MSPM0G3507。

主要功能：

- 摄像头初始化和实时图像采集。
- 灰度图转换与矩形轮廓检测。
- 矩形角点排序、面积筛选、长宽比筛选。
- 透视变换计算目标中心点。
- ST7701 屏幕实时显示识别框、角点、中心点和 FPS。
- UART2 输出目标坐标。
- 脱机版本支持触摸屏调整阈值并保存到 `/sdcard/thresholds.txt`。

### 2. MSPM0G3507 小车循迹

`MSPM0G3507/Car/Track` 是小车底盘工程，主要负责双电机小车的循迹和运动控制。工程读取 8 路灰度/循迹传感器，根据黑线位置计算偏差，通过循迹 PID 调整左右轮速度；同时结合编码器反馈和速度 PID，实现更稳定的电机输出。

主要功能：

- 8 路灰度传感器数据读取。
- 黑白阈值标定。
- 循迹数字量读取和位置判断。
- 左右轮编码器测速。
- TB6612 双电机 PWM 控制。
- 循迹 PID 和左右轮速度 PID。
- 按键切换模式、启动/停止、阈值标定、LCD 切屏。
- 按编码器距离运行指定距离后停车。
- LCD 状态显示和 VOFA 波形调试接口。

### 3. MSPM0G3507 云台步进电机控制

`MSPM0G3507/BJDJ/BJDJ` 是云台/步进电机工程，主要负责接收 K230 发送的坐标，计算目标中心相对图像中心的偏差，并通过 EMM_V5 协议控制两路步进电机进行水平和俯仰方向补偿。

主要功能：

- UART 中断接收 K230 坐标数据。
- 解析 `$$C,cx,cy,area##` 数据帧。
- 以图像中心 `(160, 120)` 为基准计算 x/y 偏差。
- 两轴步进电机位置模式控制。
- 无目标时扫描寻找目标。
- PID 模式下进行目标对准。
- 转角状态下进行额外补偿。
- 按键切换普通对准、扫描、PID 对准等模式。
- LCD 与 GPIO 状态指示。

## 三、串口通信协议

K230 向 MSPM0G3507 发送坐标数据，串口配置如下：

```text
串口：UART2
波特率：115200
数据格式：$$C,cx,cy,area##
```

数据帧示例：

```text
$$C,160,120,8600##
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `cx` | 目标中心点 x 坐标 |
| `cy` | 目标中心点 y 坐标 |
| `area` | 检测到的矩形外接框面积 |

云台工程中，`BSP/src/pid.c` 的 `UART_1_INST_IRQHandler()` 通过状态机解析该协议。解析完成后，数据会写入：

```c
uart_parsed_nums[0] = cx;
uart_parsed_nums[1] = cy;
uart_parsed_nums[2] = area;
```

## 四、K230 代码架构

### 1. 文件说明

| 文件 | 作用 |
| --- | --- |
| `K230/K230.py` | 在线运行主程序，负责实时识别矩形、计算中心点、显示画面并发送坐标。 |
| `K230/K230-脱机调阈值.py` | 带触摸屏调参界面的版本，可脱机调整阈值并保存到 K230 文件系统。 |

### 2. 主流程

1. 初始化 FPIOA，将 11、12 号引脚配置为 UART2 TX/RX。
2. 初始化 UART2，波特率为 `115200`。
3. 初始化摄像头，输入分辨率为 `1280 x 960`，实际处理帧设置为 `320 x 240`。
4. 初始化 ST7701 显示屏，并启动媒体管理器。
5. 循环获取摄像头图像。
6. 将图像转为灰度图。
7. 调用 `cv_lite.grayscale_find_rectangles_with_corners()` 检测矩形。
8. 根据面积、长宽比、对边比例筛选有效矩形。
9. 对角点进行排序，计算矩形中心。
10. 建立虚拟矩形到实际矩形的透视变换矩阵。
11. 将虚拟矩形中心映射到图像坐标，得到目标中心点。
12. 在屏幕绘制矩形、角点、中心点和 FPS。
13. 通过 UART 发送坐标数据。

### 3. 主要参数

| 参数 | 说明 |
| --- | --- |
| `canny_thresh1`、`canny_thresh2` | Canny 边缘检测阈值。 |
| `approx_epsilon` | 轮廓多边形逼近精度。 |
| `area_min_ratio` | 矩形检测内部使用的最小面积比例。 |
| `max_angle_cos` | 角度筛选参数，用于排除不接近矩形的轮廓。 |
| `gaussian_blur_size` | 高斯滤波核大小。 |
| `MIN_AREA`、`MAX_AREA` | 目标矩形面积筛选范围。 |
| `MIN_ASPECT_RATIO`、`MAX_ASPECT_RATIO` | 目标矩形长宽比筛选范围。 |
| `RECT_WIDTH`、`RECT_HEIGHT` | 虚拟矩形尺寸，用于透视映射中心点。 |
| `L_min`、`L_max` | 脱机调阈值版本中的灰度二值化范围。 |

### 4. 脱机调阈值功能

`K230-脱机调阈值.py` 支持在 K230 触摸屏上调整参数：

- `L_min`
- `L_max`
- `MIN_AREA`
- `MAX_AREA`

运行程序后，按下 K230 自带按键进入阈值调整界面。通过触摸滑块修改参数，点击保存后会写入 `/sdcard/thresholds.txt`。重新上电后，程序会优先读取保存的参数。

## 五、小车循迹工程代码架构

工程路径：

```text
MSPM0G3507/Car/Track
```

### 1. 主程序 `main.c`

`main.c` 是小车工程入口，核心流程如下：

1. `SYSCFG_DL_init()` 初始化 SysConfig 生成的外设配置。
2. `Motor_Init()` 初始化电机和编码器。
3. 初始化无 MCU 灰度传感器。
4. 读取灰度模拟值并设置默认黑白标定值。
5. 初始化循迹 PID 和左右轮速度 PID。
6. 初始化 LCD。
7. 设置左右轮初始目标速度为 `base_speed`。
8. 在主循环中执行灰度读取、循迹读取、按键处理、LCD 显示、循迹运动和停车控制。

### 2. BSP 模块说明

| 模块 | 作用 |
| --- | --- |
| `BSP/src/senser.c` | 无 MCU 灰度传感器读取、黑白标定、数字量/模拟量/归一化数据输出。 |
| `BSP/src/track_key.c` | 读取 8 路循迹传感器状态。 |
| `BSP/src/pid.c` | 循迹 PID、速度 PID、PWM 计算、刹车和定时器中断逻辑。 |
| `BSP/src/encoder.c` | 编码器初始化、计数读取、速度采样和均值滤波。 |
| `BSP/src/bsp_tb6612.c` | TB6612 双电机 PWM 控制。 |
| `BSP/src/key.c` | 矩阵按键扫描，用于切换模式、启动停止、黑白阈值标定等。 |
| `BSP/src/LCD.c` | LCD 页面显示逻辑。 |
| `BSP/src/hw_lcd.c` | LCD 底层绘图驱动。 |
| `BSP/src/hw_spi.c` | SPI/写屏底层接口。 |
| `BSP/src/vofa.c` | 上位机波形显示接口，用于调试 PID 输出等变量。 |

### 3. 循迹控制逻辑

循迹控制由 `Follow_Line()` 完成。程序根据 8 路传感器状态判断黑线位置，计算当前位置偏差，再通过 `track_pid` 输出修正量，最终改变左右轮目标速度。

速度闭环由 `pwm_calculate()` 完成。程序读取左右编码器速度，分别通过 `motor1_pid` 和 `motor2_pid` 计算 PWM 输出，再控制 TB6612 驱动左右轮。

当 `start_flag` 有效并且 `distance1 < 44 * num1` 时，小车继续循迹；达到目标距离后执行 `pwm_break()` 和 `pwm_ctrol(0, 0)` 停车。

### 4. 小车按键功能

| 按键值 | 功能 |
| --- | --- |
| `1` | 切换 `key_mode`，超过 4 后回到 0。 |
| `2` | 增加 `num1`，用于设置运行圈数/距离档位。 |
| `4` | 切换 `start_flag`，启动或停止小车。 |
| `5` | 切换 `fx_flag`，用于反向/方向相关控制。 |
| `6` | 根据当前灰度值标定黑色阈值。 |
| `7` | 根据当前灰度值标定白色阈值。 |
| `8` | 切换 LCD 显示页面并清屏。 |

### 5. 小车关键变量

| 变量 | 含义 |
| --- | --- |
| `sensor_values[8]` | 8 路循迹传感器数字状态。 |
| `Anolog[8]` | 8 路灰度传感器模拟值。 |
| `white[8]`、`black[8]` | 灰度传感器白色/黑色标定值。 |
| `base_speed` | 小车基础速度。 |
| `target_speed1`、`target_speed2` | 左右轮目标速度。 |
| `current_speeed1`、`current_speeed2` | 左右轮当前速度。 |
| `track_pid` | 循迹位置 PID。 |
| `motor1_pid`、`motor2_pid` | 左右轮速度 PID。 |
| `distance1` | 编码器累计距离，用于定距停车。 |
| `key_mode` | 当前工作模式。 |
| `start_flag` | 启动/停止标志。 |

## 六、云台步进工程代码架构

工程路径：

```text
MSPM0G3507/BJDJ/BJDJ
```

### 1. 主程序 `main.c`

`main.c` 是云台工程入口，核心流程如下：

1. `SYSCFG_DL_init()` 初始化 SysConfig 生成的外设。
2. 使能 UART1 接收中断和 TIMER1 定时器中断。
3. 初始化两路步进控制 PID。
4. 初始化 LCD 并清屏。
5. 在主循环中扫描按键，读取转角信号 GPIO，并根据 `key_mode` 选择普通对准、扫描或 PID 对准模式。

### 2. BSP 模块说明

| 模块 | 作用 |
| --- | --- |
| `BSP/src/pid.c` | UART 数据帧解析和定时器中断。 |
| `BSP/src/BJDJ.c` | 坐标误差计算、两轴步进电机位置补偿、扫描逻辑和 PID 对准逻辑。 |
| `BSP/src/Emm_V5.c` | EMM_V5 步进电机驱动协议封装。 |
| `BSP/src/key.c` | 按键扫描，用于切换模式、启动标志和反向扫描标志。 |
| `BSP/src/LCD.c` | LCD 状态显示。 |
| `BSP/src/hw_lcd.c` | LCD 底层绘图驱动。 |
| `BSP/src/hw_spi.c` | SPI/写屏底层接口。 |

### 3. 云台工作模式

| `key_mode` | 功能 |
| --- | --- |
| `0` | 空闲/待机模式，关闭运行指示。 |
| `1` | 普通坐标对准模式，收到 K230 坐标后调用 `Line_Proc()`。 |
| `2` | 扫描寻找模式，无目标时按 `fx_flag` 方向扫描，有目标后对准。 |
| `3` | PID 对准模式，调用 `Line_Proc_pid()`，对 x 轴进行 PID 补偿。 |

### 4. 核心控制函数

| 函数 | 作用 |
| --- | --- |
| `Line_Proc()` | 根据 x/y 偏差换算步进脉冲，控制两轴步进电机对准目标。 |
| `diansai_3()` | 当坐标为 0 时进入扫描；识别到目标后切回对准。 |
| `Line_Proc_pid()` | 对 x 轴坐标进行 PID 修正，同时对 y 轴做位置补偿。 |
| `turn_line1()`、`turn_line2()` | 按脉冲控制两路步进电机位置。 |
| `turn_speed1()`、`turn_speed2()` | 按速度控制两路步进电机。 |
| `Emm_V5_Pos_Control_1()`、`Emm_V5_Pos_Control_2()` | 两路步进电机位置模式控制。 |
| `Emm_V5_Vel_Control()` | 步进电机速度模式控制。 |
| `Emm_V5_Synchronous_motion()` | 触发多电机同步运动。 |

### 5. 云台按键功能

| 按键值 | 功能 |
| --- | --- |
| `1` | 切换 `key_mode`，超过 4 后回到 0。 |
| `2` | 增加 `num1` 参数。 |
| `4` | 切换 `start_flag`。 |
| `5` | 切换 `fx_flag`，影响扫描方向和状态指示。 |

## 七、运行方式

### 1. 运行 K230 程序

1. 使用 CanMV IDE K230 打开 `K230/K230.py` 或 `K230/K230-脱机调阈值.py`。
2. 确认 K230 固件中包含 `cv_lite` 模块。
3. 确认摄像头、屏幕和 UART2 引脚连接正常。
4. 运行程序后，屏幕会显示识别画面和 FPS。
5. 当识别到有效矩形时，串口会输出 `$$C,cx,cy,area##` 格式数据。

### 2. 运行 MSPM0G3507 小车工程

1. 使用 TI Code Composer Studio 打开 `MSPM0G3507/Car/work_1.theia-workspace`，或导入 `MSPM0G3507/Car/Track` 工程。
2. 确认目标芯片为 MSPM0G3507，SysConfig 和 DriverLib 路径正确。
3. 编译、下载并运行。
4. 上电后先进行灰度黑白标定，再进入循迹模式测试。

### 3. 运行 MSPM0G3507 云台工程

1. 使用 TI Code Composer Studio 打开 `MSPM0G3507/BJDJ/work_1.theia-workspace`，或导入 `MSPM0G3507/BJDJ/BJDJ` 工程。
2. 将 K230 UART2 输出连接到 MSPM0G3507 UART1 接收端，并保证双方共地。
3. 编译、下载并运行。
4. 先运行 K230 视觉程序，确认串口持续输出坐标。
5. 切换云台工程工作模式，测试普通对准、扫描和 PID 对准功能。

## 八、调试建议

- K230 识别稳定时优先保持视觉算法不变，主要通过阈值和面积范围适配现场光照。
- 如果 K230 检测不到目标，先调 `L_min`、`L_max`，再调 `MIN_AREA`、`MAX_AREA`。
- 如果下位机解析不到坐标，检查串口波特率、TX/RX 接线、共地和数据帧头尾。
- 如果小车循迹不稳定，先重新标定灰度传感器黑白值，再降低 `base_speed`，最后调 `track_pid`。
- 如果小车直线跑偏，检查左右电机方向、编码器方向和左右速度 PID 输出。
- 如果云台运动方向反了，调整 `Emm_V5_Pos_Control_*` 的方向参数，或用 `fx_flag` 验证方向。
- 如果云台对准后抖动，降低 PID 的 `Kp` 或增加中心死区判断。
- 如果转角补偿异常，检查 `zhuang_flag`、`zhuang_num` 和 `Line_Proc_pid()` 中的额外补偿脉冲。

## 九、当前代码状态说明

K230 视觉代码已经比较稳定，能够保持较高帧率运行。MSPM0G3507 侧的小车和云台代码已经具备基础功能与部分发挥功能，如果后续继续优化，建议优先从循迹稳定性、云台 PID 死区、串口数据容错和参数固化几个方向入手。
